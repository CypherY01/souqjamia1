## الفحص

```bash
pnpm contract:lint
```

Redocly اعتمادية تطوير في المستودع بالإصدار المثبت في `pnpm-workspace.yaml`. المهمة 1.3 تضيف الفحص إلى CI مع فحص تغطية المعرّفات.

## الاتفاقات المشتركة

- **الصيغة:** OpenAPI 3.1.
- **الرد الناجح:** `{ "data": ..., "meta": ... }`. والصفحات تحمل `meta.next_cursor`.
- **الخطأ:** `{ "code", "message", "field_errors", "trace_id" }`، بلا SQL ولا تتبع مكدس ولا كشف لوجود مورد خاص.
  - `field_errors` قائمة `{ field, code }`، فارغة إن لم يخص الخطأ حقلاً. رموز الحقول: `required` و`unknown_field` و`invalid_type`، ورموز قواعد الطول والصيغة مثل `too_small` و`too_big` و`invalid_format`.
  - أي عملية قد ترجع 500 `INTERNAL_ERROR` عند خلل غير متوقع، برسالة عامة ورقم تتبع فقط (المهمة 1.6).
- **الترويسات:**
  - `X-CSRF-Token` لكل طلب يغيّر الحالة، مع فحص Origin وFetch Metadata (SEC05). الرمز من API013، ومربوط برقم جلسة العضو أو بكوكي الزائر `__Host-souq-guest`. يتغير عند الدخول والخروج وتغيير الحساب، فتطلب الواجهة رمزاً جديداً بعدها.
  - `X-Trace-Id` في كل رد، ويساوي `trace_id` في جسم الخطأ (NFR13).
  - `Vary: Origin` في ردود API، ولا ترويسة `Access-Control-Allow-*` في أي رد، فلا CORS خارج الموقع نفسه (SEC04).
  - `Idempotency-Key` لإنشاء المحتوى والرسائل والعروض واللقاءات والصفقات والتقييمات والبلاغات وطلبات التوثيق، ولقرارات العروض واللقاءات (BR32).
  - `Retry-After` مع 429 و503، ومع 202 عندما يكون الطلب نفسه قيد المعالجة.
- **الصفحات:** `cursor` و`limit`، الافتراضي 20 والأقصى 50. تعليم الإشعارات يقبل حتى 100 معرّف.
- **الأموال:** هللات كأعداد صحيحة. **الوقت:** RFC3339، والخادم يخزن UTC.
- **النصوص:** الحدود بعدد المحارف (code points) بعد NFC والقص. كلمة المرور لا تُقص ولا تُطبَّع.
- **الحقول التي يحددها الخادم** لا تُقبل من العميل: البائع والمشتري والدور والحالة والشارة والتقييم. أي حقل غير معروف يُرفض (`additionalProperties: false`).

## الامتدادات

| الامتداد | المعنى |
| --- | --- |
| `x-spec-ids` | أول قيمة رقم العملية (API)، ثم FR وBR وDEC وTC المرتبطة |
| `x-access` | مستوى الوصول، في الجدول التالي |
| `x-rate-limit` | معرّفات RL، أو `supabase_auth` و`turnstile` للحدود المدمجة في Supabase Auth (DEC36) |
| `x-open-question` | رقم سؤال ما زال مفتوحاً في `plan/phase-1.md`. العملية مكتوبة حسب الاقتراح الحالي حتى يُحسم، ثم يُستبدل برقم القرار في `x-spec-ids` |
| `x-phase1-excluded` | في جذر `openapi.yaml`: العمليات المستبعدة من المرحلة الأولى، لكل منها `id` و`reason` |

## مستويات الوصول (`x-access`)

| القيمة | المعنى |
| --- | --- |
| `public` | أي أحد بلا جلسة |

| `member_reauth` | `member` مع إعادة تحقق خلال خمس دقائق (DEC38) |

| `participant` | `member` طرف في المحادثة أو العرض أو اللقاء أو الصفقة |
| `participant_or_staff` | `participant`، أو `staff` لصور البطاقة الجامعية (DEC55) وصور أدلة البلاغ (DEC43) فقط |
| `role_holder`، `role_holder_reauth` | صاحب دور إداري قبل رفع الجلسة إلى aal2 |

| `platform_owner`، `platform_owner_reauth` | دور المالك فقط بجلسة aal2 (DEC29) |
| `internal` | فحص الجاهزية الداخلي |

## العمليات المستبعدة من المرحلة الأولى (20)

القائمة برقم كل عملية وسببها في الامتداد `x-phase1-excluded` أعلى `openapi.yaml`، وهو مصدرها الوحيد.
- **المستبعد:** توثيق البريد الجامعي، وSend Email Hook، وخادم WebSocket، واسترجاع MFA اليدوي.
- **المؤجل للمرحلة الثانية:** الحضور، والنزاعات، والاستئناف، والدعم بالدفع، وتجميد الأدلة.

الأمر `pnpm check:contract-ids` يتأكد أن كل رقم من API001 إلى API119 إما مستبعد في هذه القائمة، أو موجود في `paths` مرة واحدة بالضبط وأول قيمة في `x-spec-ids` له هي نفس الرقم.

## اختيارات العقد المعتمدة

هذه نقاط لم تحسمها الوثائق، فاختارها العقد، واعتمدها المالك مع المهمة 1.1.

1. **API010 وAPI011 باقيتان** كواجهتين رفيعتين فوق MFA المدمج في Supabase، لأن تدفقات الهوية تمر عبر خادمنا. لذلك صار العدد 98 عملية بدل 96.
2. **مدخل روابط البريد** في API004 وAPI007 وAPI021 وAPI028 هو `token_hash` بدل `token` و`flow_state`، لأن AuthFlow أُلغي.
3. **`captcha_token`** في التسجيل والدخول وإعادة الإرسال والاستعادة وطلب استرجاع الحساب (DEC36).
4. **API015 متاحة لأي جلسة** حتى يعرض الحساب غير المؤكد أو المقيّد حالته (DEC58).
5. **API029 بلا حقل locale**، لأن Profile.locale هو المصدر (القسم 6.3).
6. **API041 تدعم صور البطاقة الجامعية** عبر `verification_request_id`، لأن الملحق لم يحدد عملية لرابط الستين ثانية (DEC55).
7. **API070 بلا حقل `reason`**. سبب الإلغاء `by_seller` أو `by_buyer` يحدده الخادم من المتصل (DEC56).
8. **API088 تستخدم `suspend_days` (7 أو 30)** بدل `until`، لأن المشرف يوقف 7 أو 30 يوماً فقط (DEC57).
9. **نوع المرجع `meeting_point`** بدل `location` في API094–API096 (DEC28).
10. **السبب الإداري** نص من 1 إلى 2000 محرف، والوثائق لم تحدد حداً.
11. **الحمولة الكبيرة ترجع 400** لا 413، لأن جدول الحالات في الفصل 09 لا يذكر 413.
12. **API094 وAPI100 ترجعان القائمة كاملة** بلا صفحات، لأنها قوائم صغيرة.
13. **قائمة رموز الأخطاء جديدة**. v3 يذكر `STATE_CONFLICT` كمثال فقط.
14. **قيم مختارة:** ترتيب السوق `newest` و`price_asc` و`price_desc`، وفلتر الإسناد في API083 `me` و`unassigned` و`any`، وأسماء أحداث Realtime، وترويسة `X-Probe-Token` لفحص الجاهزية.
